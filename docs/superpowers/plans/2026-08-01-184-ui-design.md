# #184 Employee Day Schedule Board — UI/Interaction Design

Design agent output, 2026-08-01, **adapted by the coordinator to the user's time-axis decision**: 8:00–17:00 real-time timeline, hour-granular columns, arbitrary minute-range time frames, multi-hour selection; expanded calendar-esque view is stretch (A5). Read alongside `2026-08-01-184-data-sync-design.md` (the data layer this consumes).

## User decisions (binding)

- Time axis: 8AM–5PM workday window, real times, assignable time frames (not fixed dayparts).
- Board visible to EVERYONE read-only; editing gated by `manage_schedule`. Dashboard tile gated (hidden from non-editors); deep link renders read-only.
- Job/PM chip popups include "Clear this slot" for editors in v1.

## Timeline grid

- Window: 8:00–17:00 (minutes 480–1020), 9 hour columns. Employee names in a fixed left column (~96w) OUTSIDE a per-row horizontal `ScrollView` — names never scroll away. Column-header hour labels render in `aboveList` (under DaySelector) sharing a `SLOT_ROW_LAYOUT` constants object (col width, chip heights) with rows so header/rows cannot misalign. Rows via `ListScreenShell` FlatList (vertical virtualized axis = employees).
- Assignments render as chips SPANNING their minute range: left offset + width computed from start/end minutes via `dayMath` helpers (`HOUR_START=480`, `HOUR_END=1020`, `minuteToX(min, colWidth)`, `chipSpan(start,end,colWidth)`). Chips: `StatusPill` tone 'primary' (job name) / 'accent' ("PM · <first name>"), numberOfLines=1. Assignments partly/fully outside 8–17 render clamped to the window edge with a small "◂/▸" off-window marker — schema is minute-general, the window is only a viewport.
- Read-only users: identical grid; chips tappable (info popups); empty cells inert muted `—` (View, not Touchable — OnCallCalendar `s.unassigned` treatment).

## Range selection (v1, gesture-safe)

Tap an empty hour cell (editors only) → `AssignmentPickerSheet` opens with that hour pre-filled (e.g. 9:00–10:00). Sheet header = graphical range editor: start/end time steppers (30-min increments, clamped 0–1440) + quick-extend chips `+1h · +2h · All day (8–5)`. Multi-hour frames = one extra tap; zero drag-vs-scroll gesture conflict inside the horizontal ScrollView.

**A5 (stretch, only after A1–A4 device-verified):** long-press-drag across cells to select a range; expanded per-employee vertical calendar view. If skipped, file a follow-up board item.

## AssignmentPickerSheet

ONE ModalSheet with internal step state — NEVER nested Modals (the live `(teams)/[id].tsx:716-776` trap: two Modals visible at once + Android touch dispatch issues).

```tsx
type Step = 'menu' | 'job-search' | 'pm-list';
useEffect(() => { if (visible) setStep('menu'); }, [visible]); // fresh per open
```
- menu: title "Assign <employee> — <range>", range editor, three themed rows: **Job**, **Production Manager**, **Create a Job** (plain TouchableOpacity rows, OnCallCalendar editorActions styling; check ui kit README for an existing row primitive first).
- job-search: `SearchablePicker` over `getOpenJobs()` options; `onSelect` → `assignJobSlot({employeeId, day, startMinute, endMinute, jobId}, userId)` → close. `onCreate={canCreateJobs ? createJobInline : undefined}` — the #173 inline pinned "+ Create" (copy `AddServiceRecordSheet.tsx:178-202` local-write pattern: generateUUID → upsertJob → appendOutbox INSERT jobs → appendLog job_created → auto-assign), gated `create_jobs`.
- pm-list: rows from `getAssignableManagers()`; single PM → auto-assign + close (skip list). Select → `assignManagerSlot(...)`.
- **Create a Job** (deliberate path): parent-owned handoff to `QuickCreateSheet` hosting `JobQuickAdd` — `onCreateJob = () => { onClose(); setQuickCreateOpen(true); }`; `DayBoardScreen` owns `pickerOpen`/`quickCreateOpen` as sibling booleans, never both true → at most one Modal mounted-and-visible. `onCreated={(e) => { assignJobSlot({...pendingRange, jobId: e.id}, userId); setQuickCreateOpen(false); }}`.
- Overlap: catch `ScheduleConflictError` → inline warning listing conflicts ("Mike already has Job X 9:00–11:00") with "Replace" (retry `{force:true}`) / "Cancel".
